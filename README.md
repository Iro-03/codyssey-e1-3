# Mini NPU 시뮬레이터

2차원 패턴과 필터의 같은 위치에 있는 값을 곱하고 누적하는 MAC(Multiply-Accumulate) 연산을 직접 구현한 Python 콘솔 프로그램이다.

## 개발환경

- Python 3.8 이상
- 외부 라이브러리 없이 표준 라이브러리 `time`, `json`, `math`, `pathlib`만 사용
- 2차원 MAC은 중첩 반복문, 1차원 MAC은 단일 반복문으로 구현

## 실행 방법

`main.py`와 `data.json`을 같은 폴더에 둔다. 해당 폴더에서 다음 명령을 실행한다.

```powershell
python main.py
```

- `1`: 필터 A, 필터 B, 입력 패턴을 각각 3행씩 입력한다. 각 행은 공백으로 구분한 숫자 3개로 구성한다. 필터 저장 내용, 두 점수, 판정, 3×3 MAC 평균 시간 및 2차원/1차원 성능 비교가 출력된다.
- `2`: `data.json`의 필터와 패턴을 읽어 케이스별 점수, 판정, 정답, PASS/FAIL을 출력한다. 이어서 3×3·5×5·13×13·25×25 성능 표, 2차원/1차원 성능 비교 및 전체 집계를 출력한다.

- `3`: 양의 정수 N을 입력해 Cross와 X 패턴을 생성한다. 입력 패턴을 Cross/+ 또는 X로 선택하면 생성한 두 필터로 판정하고 성능을 비교한다.

JSON 경로는 실행한 터미널의 위치가 아니라 `main.py`의 위치를 기준으로 결정한다. 파일은 `utf-8-sig`로 읽어 UTF-8 BOM도 처리한다.

### 사용자 입력 예시

필터 A와 입력 패턴에는 각각 다음 세 행을 입력한다.

```text
0 1 0
1 1 1
0 1 0
```

필터 B에는 다음 세 행을 입력한다.

```text
1 0 1
0 1 0
1 0 1
```

예상 결과는 A 점수 `5.0`, B 점수 `1.0`, 판정 `A`이다. 숫자가 아닌 값이나 열 개수가 잘못된 행은 안내 후 다시 입력받는다.

## 구현 요약

### 데이터 구조와 검증

패턴과 필터는 리스트 안에 행 리스트를 넣는 2차원 구조로 저장하며, `matrix[row][col]`로 접근한다.
JSON의 `filters`에는 `size_5`, `size_13`, `size_25`가 있고 각 크기에 `cross`, `x` 필터가 있다.
`patterns`의 키는 `size_{N}_{idx}`이며, 각 항목에 `input`과 `expected`가 있다.
키에서 N을 추출하여 해당 크기의 필터를 선택하고 행 수, 열 수, 숫자 자료형을 검사한다.
NaN, 무한대 및 숫자 연산 범위를 벗어난 입력이나 점수는 오류로 안내한다. JSON의 true/false는 숫자로 허용하지 않는다.
알 수 없는 라벨, 중복된 표준 필터 라벨, 필터 누락, 크기 불일치는 해당 케이스의 FAIL로 기록하고 다음 케이스를 처리한다.
파일 읽기 오류나 최상위 구조 오류는 안내 후 JSON 모드를 종료한다.

### 라벨 정규화

| 원본 표기 | 표준 라벨 |
|---|---|
| `+`, `cross`, `Cross` | `Cross` |
| `x`, `X` | `X` |

문자열 양 끝의 공백을 제거하고 소문자로 변환한 뒤 대응시킨다. 정답과 필터 키에 같은 함수를 사용하여 표현 차이로 생기는 비교 실패를 방지한다.

### MAC 및 판정 정책

`mac()`은 각 위치에서 `pattern[row][col] * filter_matrix[row][col]`을 계산해 점수에 누적한다.
`judge()`는 `abs(score_a - score_b) < 1e-9`이면 `UNDECIDED`를 반환하며, 그 외에는 점수가 큰 라벨을 반환한다.
사용자 입력 모드는 `A`/`B`, JSON 모드는 `Cross`/`X` 라벨을 사용한다.
PASS/FAIL은 판정과 정규화한 expected의 일치 여부로 결정한다. 정답이 Cross 또는 X일 때 UNDECIDED는 FAIL이다.
출력의 `:.10g`는 표시만 조절하며, 판정에는 원래 점수를 사용한다.

### 실패 원인 분석

1. 제공된 여섯 케이스는 현재의 키, 라벨 및 배열 크기 검증을 통과했다.
2. 따라서 이번 세 실패는 스키마 검증 단계가 아니라 판정과 정답의 비교 단계에서 발생했다.
3. `+`와 `cross`는 Cross로, `x`는 X로 정규화하여 표기 차이에 따른 실패를 방지했다.
4. `size_5_1`은 두 점수가 약 0.9이며 차이의 절댓값은 약 `1.11e-16`이다.
5. `size_13_2`는 두 점수가 약 7.5이며 차이의 절댓값은 약 `2.66e-15`이다.
6. `size_25_1`은 두 점수가 약 4.9이며 차이의 절댓값은 약 `1.78e-15`이다.
7. 이처럼 작은 차이는 소수의 이진 부동소수점 표현 및 누적 계산에서 생길 수 있다.
8. 세 케이스 모두 점수 차이가 epsilon인 `1e-9`보다 작아 UNDECIDED로 판정된다.
9. 데이터의 정답은 각각 X, Cross, X이므로 동점 판정과 일치하지 않는다.
10. 이번 실패는 데이터의 정답 라벨과 적용한 동점 처리 정책 사이의 불일치로 설명할 수 있다.
11. epsilon은 미세한 수치 차이를 승패로 해석하지 않도록 작동하며, 모든 케이스의 PASS를 보장하는 장치는 아니다.
12. PASS 수를 늘리기 위해 정답 데이터나 epsilon을 변경하지 않고, 관찰된 실패 원인을 기록했다.
13. 전체 6개는 통과 3개와 실패 3개의 합과 일치한다.

### 성능 측정과 시간 복잡도

두 모드 모두 `time.perf_counter()`로 MAC 함수 호출 전후를 측정한다.
같은 입력으로 10회 반복 측정한 시간의 평균에 1000을 곱해 ms로 출력한다.
입력, 출력, JSON 파일 읽기는 MAC 측정 구간에 포함하지 않는다.
측정값에는 함수 호출과 시간 측정에 따른 작은 부가 비용이 포함될 수 있다.

2026-11-05 Windows / Python 3.14.7에서 실행한 JSON 모드의 측정 예시는 다음과 같다. 시간은 실행 시점과 환경에 따라 달라진다.
3×3은 패턴 생성기로 만든 십자가를 사용하며, 나머지 크기는 첫 번째 유효 케이스의 패턴과 Cross 필터를 사용한다.
정답 비교에서 FAIL이더라도 데이터 형식과 연산이 유효하면 측정 대상으로 사용할 수 있다.

| 크기 | MAC 연산 횟수 N² | 평균 시간(ms) |
|---|---:|---|
| 3×3 | 9 | 0.000850 |
| 5×5 | 25 | 0.001150 |
| 13×13 | 169 | 0.005710 |
| 25×25 | 625 | 0.018510 |

표의 연산 횟수는 필터 하나에 대한 MAC 함수 호출을 기준으로 한다.
N개의 행마다 N개의 열을 방문하므로 한 번 호출할 때 N²회의 곱셈과 누적 덧셈을 수행한다.
따라서 MAC 함수의 시간 복잡도는 O(N²)이다.
두 필터를 비교하면 2N²회의 MAC 연산이 필요하지만 상수 배수를 제외한 시간 복잡도는 여전히 O(N²)이다.
입력 배열을 제외하면 점수와 반복 변수만 사용하므로 MAC 함수의 추가 공간 복잡도는 O(1)이다.
패턴과 필터 자체를 저장하는 공간은 O(N²)이다.
작은 배열에서는 실행 환경과 측정 비용의 영향이 커서 측정 시간이 N² 비율과 정확히 일치하지 않을 수 있다.
5×5에서 25×25로 커지면 연산 횟수는 25배, 이번 측정 시간은 약 16.1배가 된다.
고정된 호출 비용 등의 영향으로 정확한 배율은 다르지만, 크기 증가에 따라 측정 시간이 증가하는 경향을 확인했다.
O(N²)의 직접적인 근거는 두 중첩 반복문의 방문 횟수이며, 짧은 시간의 단일 측정 결과만으로 복잡도를 증명하지 않는다.
크기별 유효 데이터를 확보할 수 없으면 해당 행에 측정 불가를 표시하고 결과 요약을 계속 출력한다.

## 보너스 과제 구현

### 패턴 생성기

`generate_patterns(N)`은 Cross와 X를 각각 독립된 N×N 리스트로 생성한다.
Cross는 `row == N // 2` 또는 `col == N // 2`인 셀을 1로 설정한다.
X는 `row == col` 또는 `row + col == N - 1`인 셀을 1로 설정한다.
양의 정수를 허용하며, 짝수 크기의 Cross는 아래/오른쪽 중앙선을 기준으로 한다.
N=1에서는 두 패턴이 모두 `[[1]]`이므로 판정이 UNDECIDED가 되는 것이 정상이다.
메뉴 3은 생성한 배열을 필터와 입력 패턴으로 재사용하여 수동 입력 없이 같은 판정 및 성능 분석 함수를 실행한다.
기존 메뉴 1의 3×3 직접 입력 흐름도 유지한다. JSON 모드의 3×3 측정 데이터 역시 생성기를 재사용한다.

### 1차원 배열 MAC 및 성능 비교

`flatten_matrix()`는 행 우선 순서로 배열을 평탄화한다. 기존 `[row][col]`의 값은 `[row * N + col]`에 대응한다.
`mac_flat()`은 길이 N²의 두 리스트를 단일 반복문으로 순회하며 같은 위치의 값을 곱하고 누적한다.
기존 2차원 MAC을 기준 구현으로 유지하고, 성능 비교에서는 같은 데이터를 변환한 1차원 MAC을 함께 실행한다.
측정 전 두 결과가 정확히 일치하는지 확인한다. 두 구현의 누적 순서는 동일하다.
각 구현에 동일하게 1,000회씩 적용하고, 먼저 측정하는 구현을 반복마다 번갈아 바꾼다.
MAC 함수 호출만 측정하며, 입력/출력, 파일 읽기, 패턴 생성, 평탄화 및 점수 검증은 평균 측정 구간에서 제외한다.
두 배열을 평탄화하는 데 걸린 시간은 변환 1회(ms) 열에 별도로 표시한다.

다음은 JSON 모드에서 실제 실행한 비교 예시이다. 각 행은 같은 패턴과 Cross 필터를 사용한다.

| 크기 | 2차원 평균(ms) | 1차원 평균(ms) | 2차원/1차원 배율 | 변환 1회(ms) |
|---|---:|---:|---:|---:|
| 3×3 | 0.000606 | 0.000420 | 1.44x | 0.002000 |
| 5×5 | 0.001102 | 0.000687 | 1.60x | 0.001700 |
| 13×13 | 0.005625 | 0.003375 | 1.67x | 0.008600 |
| 25×25 | 0.019745 | 0.013960 | 1.41x | 0.067700 |

배율이 1보다 크면 해당 측정에서는 1차원 MAC이 빠르며, 1보다 작으면 느리다.
평탄화는 반복문 구조와 인덱싱을 단순하게 하지만 Python 객체의 실제 메모리 배치나 실행 환경에 따라 효과가 달라지므로 속도 향상을 보장하지 않는다.
변환 비용까지 포함하면 한 번만 계산할 때는 이점이 작아지거나 사라질 수 있다. 반복 계산에서는 변환한 배열을 재사용할 수 있다.
2차원과 1차원 MAC의 시간 복잡도는 모두 O(N²)이며, 1차원 구현도 총 N²개 원소를 처리한다.
평탄화에 O(N²) 시간과 추가 O(N²) 저장 공간이 필요하며, 변환 후 MAC 함수 자체의 추가 공간은 O(1)이다.
JSON 판정 정책과 원본 데이터는 동일하게 유지되어 전체 6개, 통과 3개, 실패 3개 결과가 유지된다.
